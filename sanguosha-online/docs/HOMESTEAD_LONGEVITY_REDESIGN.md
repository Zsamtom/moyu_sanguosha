# 三业庄园长线改造设计

状态：已实施，待持续平衡
适用范围：农场、牧场、矿山、共享规则、服务端、Web 客户端
目标版本：三业庄园 v1

## 1. 改造目标

把当前“先农场、再牧场、最后矿山”的线性成长，改造成农、牧、矿同步运行的循环经营系统。

本次改造不扩张好友玩法，重点解决以下问题：

1. 低级短周期产物经验效率过高，重度玩家可以快速刷满等级。
2. 后期金币产出远高于永久消耗，升级完成后经济失去约束。
3. 三个板块主要是等级门槛和原料消耗关系，缺少可反复规划的生产网络。
4. 当前内容存在明确终点，满级、扩满槽位后只剩重复收取。
5. 市场 LLM 只影响农场价格叙事，尚未理解完整庄园。

目标体验：

- 第一天开放农、牧、矿三个基础板块。
- 第 7 天建立第一条跨板块加工链。
- 第 30 天完成基础庄园设施。
- 第 60 天进入高级育种、深层矿山和复合订单。
- 第 90 天完成首个赛季研究目标。
- 满级后仍可通过订单组合、收藏、研究和世界事件产生新决策。

## 2. 设计原则

### 2.1 三业平等

农场不是主玩法，牧场和矿山也不是附属资源点。每个板块必须：

- 拥有自己的短期决策；
- 独立提供基础收益；
- 向其他两个板块输出关键资源；
- 接受其他板块的效率增益；
- 在联合订单和长期建设中具有不可替代的作用。

### 2.2 软联动，不制造死锁

跨板块加工提供更高收益和长期进度，但基础循环不能因为缺少一种资源完全停止。

- 基础原料始终可以通过本板块恢复。
- 必需原料可以从 NPC 市场高价补购。
- 联合生产提高效率，不是登录和继续游戏的硬门票。
- 事件不能无预警摧毁长期成果。

### 2.3 决策延寿，不靠纯数值延迟

不采用简单扩大经验阈值、增加等待时间的方式延长寿命。长期性来自：

- 有限设施队列形成的机会成本；
- 市场、天气和订单组合变化；
- 品种、动物特质、矿层与遗物收藏；
- 城镇工程和研究带来的永久改变；
- 软赛季提供的新生产问题。

### 2.4 规则权威，LLM 只做导演

LLM 可以选择经过验证的候选事件并生成叙事，但不能：

- 任意生成金币、物品或倍率；
- 绕过等级和库存校验；
- 直接修改成熟时间和掉落概率；
- 决定操作是否合法；
- 保存无限长度的玩家输入或对话。

## 3. 三业资源循环

| 板块 | 核心产出 | 输入到其他板块 | 获得的反哺 |
|---|---|---|---|
| 农场 | 作物、棉花、药草 | 饲料、口粮、麻布、加工原料 | 有机肥、矿物肥、工具、灌溉设备 |
| 牧场 | 蛋奶、羊毛、兔绒、皮革、粪肥 | 食品、纺织、防护、肥料原料 | 饲料机、围栏、保温设备、矿物盐 |
| 矿山 | 煤、金属、石料、磷矿、盐 | 农具、机械、建筑材料、矿物肥 | 口粮、布袋、防护服、绳索 |

核心闭环：

```text
农场作物 → 饲料 → 牧场产品 → 肥料 → 农场增产
```

```text
矿石 → 工具与机械 → 农场/牧场效率提升
```

```text
农场棉花 + 牧场羊毛/兔绒 → 矿山防护 → 深层矿脉
```

## 4. 统一成长体系

### 4.1 当地声望与全局名望

声望分成两个不会混用的层级：

- 当地声望：青禾镇和霜岭镇分别记录。解决当地问题、完成本地项目获得，
  用于本城镇产业升级和地标修复。
- 商会名望：跨城镇共享。解决霜岭问题会获得 1 点，修复地标阶段会获得额外
  名望，用于未来城镇解锁和跨城商路。

金币、研究点和商会名望全城镇共享；特色物资、当地声望、产业等级和地标进度
按城镇隔离。这让玩家到新城镇时需要重新建设，但不会觉得旧城镇积累全部作废。

### 4.2 板块专精

- 农场专精：土壤、天气适应、轮作、育种。
- 牧场专精：饲料配方、健康、繁育、动物特质。
- 矿山专精：勘探、加固、冶炼、深层矿脉。

### 4.3 设施研究

长期资源消耗集中在设施解锁、升级和研究，而不是高额日常维护。

首批设施：

| 设施 | 主要输入 | 主要输出 |
|---|---|---|
| 磨坊 | 小麦、玉米 | 面粉、粗饲料 |
| 饲料厂 | 作物、矿物原料 | 高级饲料 |
| 肥料厂 | 作物残渣、牧场副产、矿物 | 复合肥 |
| 厨房 | 作物、蛋奶、燃料 | 食品与订单商品 |
| 纺织坊 | 棉花、羊毛、兔绒 | 布料、防护用品 |
| 冶炼炉 | 煤、矿石 | 金属锭 |
| 机械工坊 | 金属、布料、牧场材料 | 农具、牧场设备、矿山设备 |

### 4.4 图鉴与研究

- 变异作物和稳定品系；
- 动物特质和稀有毛色；
- 矿层、矿物和遗物；
- 配方首次完成；
- 季节研究和城镇工程。

图鉴提供永久但可控的横向增益，不能形成不可追赶的指数增长。

## 5. 统一订单

### 5.1 订单层级

| 类型 | 周期 | 用途 |
|---|---|---|
| 单板块订单 | 数十分钟到 1 天 | 教程和基础周转 |
| 双板块订单 | 1 到 3 天 | 建立产业链 |
| 三板块工程 | 3 到 14 天 | 庄园与城镇长期建设 |
| 赛季研究 | 6 到 8 周 | 满级后的持续目标 |

### 5.2 首批订单模板

- 谷仓补给：小麦、玉米。
- 早餐供应：面粉、鸡蛋、牛奶。
- 冬季工作服：棉花、羊毛、煤。
- 矿工补给：胡萝卜、鸡蛋、兔绒、铁矿。
- 温室骨架：棉花、肥料、铁锭。
- 庄园机械化：铜矿、铁锭、羊毛和金币。

订单奖励由服务端模板固定，包括：

- 金币；
- 庄园声望；
- 研究点；
- 限定但可追赶的收藏进度。

## 6. 世界事件与天气

事件必须提前展示影响，并提供至少两个有效选择。

### 6.1 已落地的权威规则

- 每个庄园日使用北京时间（UTC+8）切换天气、订单和事件。
- 晴朗、温和降雨、高温热浪、霜冻分别影响三业产量和本轮生产工期。
- 播种、投喂、开采开始时把当前倍率固化到该轮生产；后续天气切换不会追溯改写结果。
- 矿山渗水和突发寒潮是持续 3 天的低频灾害。未处理时逐日升级，持续改变真实生产函数。
- 渗水未处理会降低矿石产量并延长采掘工期；灾后仍未处理会使矿山防护下降一级。
- 寒潮未处理会降低农场、牧场产量并延长工期；灾后仍未处理会损伤土壤和牧群健康。
- 事件选项在 Web 界面展示真实库存、缺口和金币成本；库存不足时按钮与服务端规则一致地禁用。

长期抗灾建设：

| 设施 | 长期作用 | 永久消耗 |
|---|---|---|
| 气象站 | 削减恶劣天气惩罚，一级后显示明日预报 | 金币、研究点、铁锭 |
| 矿山排水网 | 削减渗水造成的矿山减产与延时 | 金币、研究点、铁锭 |
| 三业防护棚 | 削减寒潮对农场和牧场的影响 | 金币、研究点、铁锭 |

灾害期不是纯惩罚窗口。每次灾害中，每个板块可启动一次应急增产：

| 板块 | 行动 | 消耗 | 当前灾期效果 |
|---|---|---|---|
| 农场 | 温室抢种 | 土壤改良剂 | 产量 +15%，工期 -10% |
| 牧场 | 强化营养 | 强化饲料 | 产量 +15%，工期 -10% |
| 矿山 | 应急排采 | 矿工防护套装 | 产量 +18%，工期 -12% |

日常土壤、牧群、矿层专精仍然生效，因此玩家可以通过“专精正增益 +
韧性设施减灾 + 灾期加工品增产”主动抵消甚至反超灾害惩罚。应急增益在灾害
结束后自动清除，避免成为永久指数增长。

### 6.2 真实天气服务接入研究

可以接入真实天气，但不应让外部 API 直接写入产量倍率。推荐增加
`WeatherProvider` 适配层，把外部数据先归一为本项目固定的四种天气 ID，再由
现有权威规则计算数值：

```text
外部天气/预警 API
        ↓
缓存、超时、数据新鲜度校验
        ↓
固定映射：clear / gentle_rain / heatwave / frost
        ↓
现有服务端倍率模板
        ↓
播种、投喂、开采时固化
```

候选方案：

- [Open-Meteo Forecast API](https://open-meteo.com/en/docs)：支持坐标、
  小时/日预报、温度、降水、阵风、土壤湿度等，适合作为无需游戏账号定位的
  预报数据源。
- [和风天气实时天气](https://dev.qweather.com/docs/api/weather/weather-now/)：
  支持中国城市/经纬度和近实时观测，适合国内部署。
- [和风天气预警](https://dev.qweather.com/docs/api/warning/weather-alert/)：
  可读取官方极端天气预警，适合只触发“灾害候选”，仍由游戏规则决定严重度、
  持续时间和数值。

接入约束：

1. 玩家主动选择城市或虚拟庄园区域，不默认收集精确定位。
2. 外部结果按区域和游戏日缓存，不能在每次操作时请求。
3. API 超时、限流、陈旧或结构异常时立即回退到当前确定性天气。
4. 真实预警只提高合法灾害候选权重，不能绕过 3 天上限和减灾选项。
5. 多人公平模式可统一使用服务器城市；个性化天气仅用于独立庄园。

当前版本先启用确定性模拟天气，已保留固定天气 ID 和独立数值映射边界；
真实天气适配器可在配置地理区域和数据服务条款后接入，不影响存档结构。

首批事件：

### 持续干旱

- 农场照料需求增加；
- 牧场清洁成本上升；
- 矿山地下水下降，稀有矿脉发现率提高；
- 可选择建设水井、降低种植规模或扩大勘探。

### 丰收庆典

- 食品和纺织订单增加；
- 直接出售基础原料的价格降低；
- 加工设施速度提高；
- 完成庆典工程获得展示收藏。

### 山体渗水

- 矿井需要铁材和纺织防护；
- 农田短期自动获得水分；
- 可选择加固矿山、引水灌溉或暂停深层勘探。

### 寒潮

- 热带作物受影响；
- 牧场需要保温；
- 煤炭和纺织品需求上升。

世界事件的数值效果始终由规则引擎定义。LLM 只选择候选和生成故事。

## 7. LLM 世界导演

### 7.1 输入

只向 LLM 提供压缩后的结构化状态：

- 三个板块等级与主要短缺/过剩；
- 已建设设施；
- 最近订单和事件 ID；
- 当前世界事件候选；
- 玩家近期选择摘要；
- 可公开的 NPC 关系事实。
- 当前城镇、当地声望和全局商会名望；
- 本地特色库存、当前待解决问题与地标修复阶段。

不发送完整存档、会话密钥、其他玩家私有库存。

### 7.2 输出

LLM 只能返回：

- 候选事件 ID；
- 标题；
- 简短叙事；
- NPC 台词；
- 对固定选项的解释；
- 不带执行权的经营建议。

输出必须经过结构校验；失败、超时或越界时使用确定性规则回退。

### 7.3 候选执行协议

```text
规则引擎构造合法候选
        ↓
LLM 返回 candidateId + narrative
        ↓
服务端确认 candidateId 存在
        ↓
执行候选中预定义的固定效果
        ↓
记录 eventId，不保存无限对话
```

沿用现有农场市场导演的候选选择模式，扩展为庄园导演，不允许 LLM 直接生成数值。

## 8. 时间节奏

当前版本固定为 **1 倍时间**。不提供用户自定义时间倍率，也不在存档中保存
倍率字段。所有倒计时、跨日刷新、天气、灾害和订单都只使用服务端权威时间，
从而避免不同城镇、离线结算和多人访问出现时间分叉。

| 系统 | 主要周期 |
|---|---|
| 农场 | 5 分钟到 18 小时 |
| 牧场 | 30 分钟到 12 小时 |
| 矿山 | 2 到 24 小时 |
| 加工设施 | 15 分钟到 8 小时 |
| 普通订单 | 当天 |
| 城镇工程 | 3 到 14 天 |
| 软赛季 | 6 到 8 周 |

一次典型登录控制在 3 到 8 分钟：

1. 收取三个板块的完成项；
2. 调整设施队列；
3. 提交订单；
4. 阅读天气和事件；
5. 安排下一轮生产。

## 9. 数据与架构

### 9.1 现有状态保持独立

- `farm_state`
- `ranch_state`
- `mine_state`

继续保存各板块权威状态，保证旧存档兼容和单板块规则清晰。

### 9.2 新增庄园状态

新增 `homestead_state`，承载：

- 庄园 revision；
- 声望与研究点；
- 加工品库存；
- 已建设设施和生产队列；
- 当前订单；
- 当前世界事件；
- 今日天气、持续灾害、韧性设施和灾期增产状态；
- LLM 叙事；
- 长期统计。

新增 `homestead_state_quarantine` 隔离无法恢复的庄园存档。

### 9.3 跨板块操作

新增共享领域模块 `shared/src/homestead.ts`：

- `createHomesteadGame`
- `refreshHomesteadGame`
- `applyHomesteadAction`
- `getHomesteadGameView`
- `assertRestorableHomesteadGameState`
- 配方、订单、事件模板

跨板块操作必须同时校验 farm、ranch、mine、homestead 四个 revision，并在单个数据库事务中保存。

### 9.4 API

新增：

- `GET /api/homestead`
- `POST /api/homestead/actions`

首批 action：

- 建设设施；
- 启动加工；
- 收取加工品；
- 完成联合订单；
- 刷新到期订单；
- 选择世界事件选项。

深度扩展 action：

- 解锁研究节点；
- 升级加工设施；
- 制定每日轮作计划并选择是否使用改良剂；
- 执行每日牧群饲料方案；
- 升级矿山防护并勘探指定矿层；
- 与三位庄园顾问按主题交流；
- 领取软赛季里程碑奖励。
- 升级气象站、排水网和防护棚；
- 在灾害期启动农、牧、矿应急增产。

上述 15 类庄园操作均由同一个权威 reducer 执行，统一校验四个
revision，并在 Web 庄园总览中提供可见入口。第一阶段存档缺少深度字段时
会自动补建默认状态，不隔离或重置原有存档。

- [x] 事件成本、按钮条件和客户端倒计时与服务端一致
- [x] 真实天气 API 适配边界与回退方案

### 完整改造落地状态

- 农场、牧场、矿山各有一次每日深度行动，并直接改变对应真实库存 revision。
- 土壤健康、牧群健康会按天衰减，轮作、营养和防护产生受上限约束的横向增益。
- 10 个研究节点包含前置条件、声望门槛和固定研究成本。
- 7 类设施均支持三级升级；升级影响加工时间和收取产量。
- 3 位 NPC 各有两个合法话题，最多保存 8 条结构化事实，不保存无限对话。
- LLM 只能选择合法事件并生成展示文本；执行数值仍全部来自规则模板。
- 软赛季持续 8 周，包含固定积分来源、3 档可追赶奖励和 45 项庄园图鉴。
- Web 对所有庄园服务端 action 设有静态可达性测试，防止后续出现 API 已存在但界面缺入口。
- 软赛季三档目标调整为 150/500/1200 分，最终奖励需要完成“季节经营学”。
- 未研究城镇协作网络时 NPC 只保留 2 条记忆；研究后扩展为 8 条跨日事实。
- 农、牧、矿从第一天同步开放基础循环，高级动物和深层矿脉继续由等级控制。
- 三业客户端按服务端固化倍率重算预计产量，避免按钮、文字和最终结算不一致。

## 11. 第一阶段验收标准

第一阶段完成时必须满足：

1. 新用户可创建庄园状态，旧用户进入时自动补建，不修改原三业存档。
2. 至少存在 6 个加工设施、8 个跨板块配方和 4 个联合订单模板。
3. 至少一个配方同时消耗农场、牧场、矿山资源。
4. 加工启动、完成和收取具有权威时间校验。
5. 联合订单从真实三业库存与加工库存扣除资源。
6. 跨状态保存具备事务性，revision 冲突返回 409。
7. 存档校验失败时仅隔离庄园状态，不丢弃农场、牧场和矿山。
8. 共享规则、服务端路由、Web API 均有测试。
9. 类型检查、测试和生产构建通过。

完整阶段还必须满足：

10. 农、牧、矿三个深度动作可在同一天分别完成，且互不占用彼此的每日次数。
11. 研究、设施升级、防护升级、NPC 对话和赛季奖励均不能由客户端注入成本或收益。
12. 第一阶段庄园存档可自动迁移出研究、专精、NPC、赛季、图鉴和建议状态。
13. 每个深度 action 都能从 Web 界面到达，并具有禁用原因或资源条件提示。
14. LLM 叙事越界、缺失或调用失败时，规则建议和固定事件仍可独立运行。
15. 天气、灾害、韧性和应急增产必须影响真实生产结果，而不只改变展示文本。
16. 外部天气服务不可用时，确定性规则天气仍能独立运行。

## 12. 后续平衡指标

上线后至少记录：

- 不同配方的使用率；
- 三个板块的活跃占比；
- 原料直接出售与加工消耗比例；
- 订单完成率与放弃率；
- 设施队列空闲时长；
- 玩家卡住的原料类型；
- 世界事件选择分布；
- LLM 回退率、延迟和每活跃用户成本；
- 第 7、30、60、90 天仍存在的未完成长期目标数量。

预期结果：

- 基础内容寿命由 1 到 2 周提高到 30 到 60 天；
- 收藏、研究和软赛季提供 90 天以上目标；
- 三个板块的日活操作占比均不低于 20%；
- 不存在长期占优的单一短周期刷级策略。

## 13. 多城镇架构与第二城镇

### 13.1 为什么第二城镇选择霜岭镇

第二城镇不是把青禾镇数值换皮，而是用高寒环境验证“同一规则框架、不同资源
闭环”。这种新增区域、保留旧积累、再开放独立经营空间的方式与长线经营游戏
常用的横向扩展方向一致；例如《星露谷物语》1.5 的官方更新加入 Ginger Island
及可解锁的岛屿农场，而没有删除原农场：
[官方更新说明](https://www.stardewvalley.net/stardew-valley-1-5-update-full-changelog/)。

霜岭镇首批内容：

| 板块 | 生产 | 输入 | 基础产出 | 基础工期 |
|---|---|---|---|---|
| 冻土农场 | 培育雪薯 | 无 | 雪薯 ×3 | 8 分钟 |
| 牦牛牧场 | 照料牦牛 | 雪薯 ×1 | 牦牛奶 ×2 | 16 分钟 |
| 霜晶矿场 | 勘采霜晶 | 牦牛奶 ×1 | 霜晶 ×2 | 24 分钟 |

冻土农场永远无需金币或上游原料，因此即使玩家把全局金币和本地库存全部耗尽，
仍可从雪薯重新启动三业循环。每个产业可升到 3 级，每级增加 1 份产出并缩短
10% 工期；升级消耗全局金币、霜岭当地声望和霜晶。

### 13.2 当地问题与地标目标

当地问题按固定顺序开放：

1. 积雪封锁补给山路；
2. 供水管网冻裂；
3. 雪崩封闭旧矿道。

每个问题都消耗至少两个产业的本地资源，并奖励金币、霜岭当地声望、研究点和
1 点商会名望。修复“山地热力站”分为 3 个阶段，需要问题进度、当地声望、
金币和三业物资；地标奖励同时提高当地声望与商会名望。这构成：

```text
三业生产 → 解决当地问题 → 当地声望 → 产业升级
                         ↘ 地标修复 → 商会名望 → 后续城镇
```

### 13.3 后续城镇顺序

本次只实现霜岭镇，数据结构按 `townId → definition/state/view` 预留扩展。
推荐后续顺序：

1. **潮汐港**：第三城镇。引入潮汐窗口、水产养殖、盐矿和冷链加工，先扩展
   “时间窗口与保鲜”决策，而不是继续叠加普通作物。
2. **赤岩城**：第四城镇。引入缺水农业、驼畜、铜盐矿与太阳能公共工程，
   加强水和能源的跨产业配置。
3. 后续更新优先增加能改变经营方法的新城镇，不优先增加只换名称和售价的城镇。

这个顺序让新城镇依次验证“闭环差异、时间窗口、稀缺资源”，避免内容扩张变成
纯数值膨胀。GDC 的长线运营与游戏经济演讲也反复强调长期内容需要持续的系统
选择和可控资源汇，而非只有一次性内容：
[Evergreen Games](https://gdcvault.com/play/1035653/The-Art-Science-of-Evergreen)、
[长线经济设计](https://gdcvault.com/play/1027266/Free-to-Play-Summit-Building)。

## 14. 全品类增值经济

结论：现在每一种青禾镇初级农产品、牧场产品和矿物都至少有一条服务端权威的
非直售路线。配方会生产实体二级、三级物品；增值项目表示交由合作社、公共工程
或外镇商会进一步加工。增值项目每天每项最多完成一次，收益约比同批原料按基础
售价直售高 25%～50%，以组合库存和每日次数换取溢价，不能无限刷金币。

| 增值项目 | 覆盖的初级产品 | 层级 |
|---|---|---|
| 河谷调味酱 | 番茄、胡萝卜 | 二级加工 |
| 双莓果酱 | 草莓、蓝莓 | 二级加工 |
| 葵油瓜果联运箱 | 向日葵、西瓜 | 二级加工 |
| 珍果礼盒 | 葡萄、火龙果 | 三级商路 |
| 合作社谷物包 | 小麦、玉米、南瓜 | 公共项目 |
| 乳蛋烘焙供应 | 鸡蛋、鸭蛋、牛奶、羊奶 | 二级加工 |
| 复合保温织物 | 兔绒、羊毛、棉花 | 三级加工 |
| 公共设施合金 | 煤、铁、铜 | 三级工程 |
| 商会珠宝委托 | 银、金、晶簇 | 三级商路 |

霜岭镇的三种初级物资同样不只用于直售：雪薯喂养牦牛，牦牛奶支持采矿，三种
物资共同用于当地问题、产业升级和热力站修复。自动化测试会遍历全部 12 种作物、
6 种牧场产品和 6 种矿物；任何新增初级资源若没有增值项目，测试会直接失败。

## 15. UI 与规则一致性审计

- 庄园总览按“今日决策 / 产业经营 / 长期成长”分区，默认只展示今日决策；
- 城镇选择单独置顶，青禾详细农牧矿页面在导航中明确标记，避免误认为霜岭页面；
- 无灾害时不显示不可操作的灾期行动；
- 霜岭生产倒计时在客户端实时刷新，但收取合法性仍由服务端校验；
- 所有按钮只发送 action ID 和必要参数，价格、产量、奖励、声望和前置条件均由
  服务端模板决定；
- 全部 action 有静态界面可达性测试，城镇闭环、零金币恢复、当地/全局声望隔离、
  每日限次、旧存档迁移有领域测试；
- 四状态 revision 冲突继续返回 409 并触发客户端静默刷新，防止并发重复结算。
