# 双城镇三业庄园：玩法与实施说明

状态：双城镇长期经营版
适用城镇：青禾镇、霜岭镇
预留城镇：潮汐港、赤岩城
时间规则：当前固定 1 倍时间，不开放个人时间倍率

## 1. 这次改造要解决什么

庄园不再是“把农场、牧场、矿山分别点到满级”的三个孤立页面，而是一套跨产业、跨城镇的长期经营游戏：

- 短期目标是安排三业生产、加工、订单和灾害应对。
- 中期目标是改善土壤、牧群与矿山防护，完成本镇独立研究、深度经营和基础设施。
- 长期目标是积累当地声望、建设跨城供应链，并通过 100 项以上的难度图鉴获得永久荣誉。
- 满级以后仍需支付加工运营费、交通费、物流机会成本和韧性维护投入，不能只靠囤积初级产品无限增长。
- LLM 被定位为“世界导演”：编排每日世界节拍、地方顾问、因果叙事、跨日伏笔和行动焦点，但不能创造数值、替玩家操作或绕过规则。

游戏的主要吸引点不是单次收菜，而是“同一笔资源应该拿去扩产、加工、交订单、修灾害，还是投资下一座城镇”的持续取舍。

## 2. 双城镇模块化结构

```text
玩家庄园账户（全局）
├─ 金币、商会名望、商店道具、每日物流
├─ 两镇分别保存的研究点与研究树
├─ 当前所在城镇、交通记录
└─ 各城镇解锁与摘要进度

青禾镇庄园包（独立）
├─ 农场
├─ 牧场
├─ 矿山
├─ 加工、订单、独立研究、本地顾问、永久荣誉
├─ 通用基础设施、青禾特色设施
├─ 当地声望、天气、灾害
└─ 本镇库存与生产任务

霜岭镇庄园包（独立）
├─ 农场
├─ 牧场
├─ 矿山
├─ 加工、订单、独立研究、本地顾问、永久荣誉
├─ 通用基础设施、霜岭特色设施
├─ 当地声望、天气、灾害
└─ 本镇库存与生产任务
```

青禾镇和霜岭镇使用同一套规则引擎和页面结构。霜岭镇不是青禾镇总览里的附属小游戏，也没有简化生产模式。两镇的差异来自完整的本地内容、研究、顾问和特色设施：

| 内容 | 青禾镇 | 霜岭镇 |
|---|---|---|
| 环境 | 温润河谷 | 高寒山地 |
| 现实天气锚点 | 郑州 | 拉萨 |
| 作物 | 小麦、玉米、番茄等 12 种 | 霜麦、雪薯、极光果等 12 种 |
| 动物与产品 | 鸡、牛、羊等 6 条产品线 | 雪羽鸡、牦牛、绒山羊等 6 条产品线 |
| 矿产 | 煤、铁、铜、金等 6 种 | 褐煤、磁铁矿、霜银、霜晶等 6 种 |
| 加工品 | 河谷食品、饲料、织物、合金等 | 高寒食品、营养品、耐寒合金、保温矿务品等 |
| 事件与灾害 | 河谷天气、渗水、风雹、旱情 | 白灾、雪崩、轨道结冰、春融、高原干旱等 |
| 研究树 | 土壤、水利、河谷联运、庄园荣誉 | 冻土、地热、雪崩物流、极光荣誉 |
| 核心操作节奏 | 农场轮作 → 牧场回肥 → 矿务排水 | 矿山热脉 → 农场供热 → 牧棚余热 |
| 顾问 | 林禾、苏岚、乔岩 | 洛桑次仁、德吉央金、索朗多吉 |
| 特色设施 | 河谷水利实验站、合作社冷链中心 | 地热温室群、雪崩防控与热力调度站 |

新增城镇时只注册城镇定义和内容包，不复制一套服务端与前端逻辑。每个城镇都必须提供完整的作物、动物、矿产、加工、订单、事件、天气和灾害内容。

## 3. 城镇解锁与交通

霜岭镇是第二座开发城镇，解锁条件为：

- 青禾镇农场 5 级；
- 青禾镇牧场 4 级；
- 青禾镇矿山 3 级；
- 青禾镇当地声望 30；
- 完成“城镇协作网络”研究；
- 支付 800 金币开发费。

解锁不会自动搬迁。玩家确认出发后才会支付交通费并切换当前城镇：

- 青禾镇与霜岭镇单程基础票价为 120 金币；
- 商会联运票售价 50 金币；
- 联运票仅让下一次客运票价减半，即支付 60 金币，并在使用后消耗；
- 金币全城镇共享，因此解锁、交通和新城建设都是成熟账户的持续金币出口；
- 每个城镇的当地声望、产业等级、库存、正在进行的任务、地标和灾害分别保存。

切换城镇、解锁城镇、购买道具和使用加速卡由账户事务统一结算。客户端必须同时提交城镇 ID 和版本号；旧页面或并发页面不能在玩家已经换城后误操作另一座城镇。

如果全局账户记录缺失但两镇存档仍完整，服务端会从最新的完整城镇包重建账户摘要，保留已经永久解锁的城镇、最高商会名望和研究进度，不会把霜岭镇重新锁回去。单实例内使用有序用户队列，多实例 PostgreSQL 部署再使用按用户排序的会话级 advisory lock；锁和本次账户读写复用同一数据库连接，不会在连接池满载时拿着锁等待第二条连接。好友双人操作也按固定用户 ID 顺序加锁，避免交叉等待和最后写入覆盖。

## 4. 三业生产和加工玩法

### 4.1 农场

农场负责种子购买、种植、成熟、收获、市场出售和轮作管理。天气、土壤健康、研究、灾害与应急行动会共同影响开始生产时固化的工期和预计产量。

作物既可直售，也可用于：

- 动物饲料；
- 二级或三级加工；
- 联合订单；
- 合作社增值项目；
- 灾害修复和城镇工程。

### 4.2 牧场

牧场负责购买动物、投喂、产品形成、收取、出售和牧群营养。每种动物使用当前城镇的作物作为饲料，动物产品又会成为矿山补给、加工与公共项目原料。

动物是需要至少约 4 个净生产周期才能回本的长期资产，而不是买入后一两轮就回本的一次性印钞机。每次投喂除饲料外还支付垫料和基础诊疗养护费；出售动物只回收约一半购入资金。入门母鸡的购入价低于一单位晚期金矿价值，避免资产价签与稀有资源的直觉倒挂。

牧群健康和已发现特质具有实际数值效果：

- 高产提高产出；
- 稳定缩短工期；
- 强健抵消部分恶劣环境惩罚；
- 繁育力和稀有毛色提供受上限约束的产出增益。

### 4.3 矿山

矿山负责矿脉选择、口粮和支护物资准备、勘探、开采与收取。矿山必须消耗本镇牧场产品和金币，避免形成脱离农牧业的独立刷钱循环。

矿山防护、排水网、天气、灾害和地层勘探会改变产量与工期。山体渗水、雪崩或轨道结冰若未处理，可以继续影响开采和物流，而不是只显示一段文字。

支护不再是假选择：抵达风险点却不加固会损失 1 份矿，及时加固则在基础产量上额外获得 1 份矿，两者相差 2 份。玩家需要比较支护材料、矿物价格和当前灾害风险，而不能无脑永远维修或永远忽视。

### 4.4 二级、三级产品和非直售用途

两座城镇都提供完整的九条加工配方链，并同时包含二级和三级产品。每个配方都具有：

- 正数原料成本；
- 正数持续运营金币成本；
- 权威生产时间；
- 有界的增值空间；
- 对应设施和等级条件。

每座城镇提供至少九条本地增值项目路线，覆盖该镇全部 12 种作物、6 种牧场产品和 6 种矿产；在此之外再增加一条必须消耗异地货箱的联动项目。初级产品因此至少有一条非直售用途。增值项目按天限次并消耗每日物流，不能把同一条高收益路线无限重复。

设施升级只改善加工工期和固定配方产出，不再按等级无限叠加批次倍率；自动化研究则以有上限的工期减免进入三业规则。这样可以提高周转效率，却不会让单份配方在满级后凭空变成数倍产出。订单和增值路线仍应与当日直售价比较：高声望公共服务单可能少赚金币，高价市场期也可能更适合直接出售。

所有农、牧、矿百分比修正都按小数精度在服务端累计，界面和单次结算仍只显示整数。基础产量 6 遇到 +15% 时精确值为 6.9，首轮结算 7 并把 -0.1 余数带入下一轮；遇到 -15% 时首轮结算 5 并把 +0.1 带入下一轮。连续十轮会分别得到 69 和 51，而不是把每轮小数永久丢掉。余数只保存在权威存档中，客户端不能提交或修改。每日事件选项会显示并固化当天的三业产量、工期、买入价和售价影响；研究、顾问、深度经营、基础设施、天气和灾害也都直接进入同一套三业规则。

### 4.5 本地经营节奏改变核心操作

城镇差异不再只靠换名称和素材。每天三项深度经营还要按本镇顺序组织：

- 青禾镇的“河谷水肥循环”为农场轮作 → 牧场回肥 → 矿务排水。每完成一环就立即获得累积效果，三环闭合后同时改善农牧矿周转并提高当日出售价格；
- 霜岭镇的“雪线地热供能”为矿山热脉勘定 → 农场温室供热 → 牧场余热利用。能源端必须先行，完成后主要强化高寒农牧产量和全网工期；
- 顺序错误不会扣除已经获得的阶段收益，但某产业每日只能深度经营一次，因此可能使当日循环无法完成；界面会明确提示并让玩家规划次日；
- 完整循环次数也是本镇研究门槛，保证这种地方操作不是可忽略的展示卡。

## 5. 每日物流与成熟期取舍

玩家每天拥有 6 点全局物流能力：

- 普通增值项目消耗 1 点；
- 高阶增值项目消耗 2 点；
- 联合订单消耗 2 点；
- 灾期紧急调度消耗 1 点。
- 每批跨城特色货运消耗 1 点，并另付固定运费。

物流不足时，服务端拒绝结算，前端同时显示明确禁用原因。玩家必须在订单、加工外运和灾害应对之间选择，而不能一天完成所有高价值行为。

双城联动不是共享本地仓库。玩家必须在产地用当地农、牧、矿与加工品装成固定货箱；发车立即扣原料，货物按服务器时间运输，抵达后还必须前往目的地领取。当前共有 6 条货运路线，每个方向 3 条：基础特产箱、民生/药膳协作箱和高阶工程材料箱。到货进入独立“跨城货栈”，只能以整箱形式参与对应目的地项目。高阶路线还要求本镇联运研究、声望和二级基础设施，形成“先建设产地能力—组织货运—在目的地追加本地原料—完成联动项目”的完整链路。

成熟期主要金币与资源出口包括：

- 新城镇开发费；
- 每次跨城交通费；
- 每批加工运营费；
- 每轮牧场投喂的垫料与基础诊疗费；
- 设施升级与矿山防护；
- 气象站、排水网和三业防护棚；
- 研究项目；
- 灾害修复与紧急增产；
- 每日轮换并有单品日限购的商会物资；
- 纯收藏性质的高价纪念品。

这些出口分别解决扩张、效率、安全、便利和收藏需求，不依赖简单提高所有物品价格。

## 6. 当地声望与商会名望

系统明确区分两种长期进度：

### 当地声望

- 青禾镇和霜岭镇分别记录；
- 通过本镇订单、增值项目、公共事件和地标工程获得；
- 用于本镇进阶、地标和后续城镇条件；
- 会因为可理解、可避免的经营后果下降；
- 最低为 0，不会变成负数。

当前声望下降来源包括：

1. 已经发生的灾害跨日仍未处理：按实际生效日逐日提高严重度并扣除，同一次灾害从发生到最终处置累计最多扣 12 点，且不会超过现有声望；
2. 个别高利润但损害社区利益的事件选项：例如占用公共会场经营摊位会获得更多金币，但损失 3 点当地声望。

现实天气本身不会无提示直接扣声望。玩家先看到灾害、影响板块、严重度、修复要求和持续后果；只有灾害已经发生后仍持续忽视，才承担声望损失。已及时处理或缓解的灾害不会继续扣声望。

支付声望的事件选项会先校验余额，声望不足时不能执行。临时处置只延缓眼前压力，不会标记灾害已解决；同一次灾害最多执行一次临时方案，也不会重复增加事件统计、荣誉进度或永久里程碑。玩家仍可随后选择彻底处置。已经永久解锁的城镇不会因当地声望下降而重新上锁，因此声望下降会压缩后续经营选择，却不会制造无法进入自己庄园的死局。

### 商会名望

- 跨城镇共享；
- 来自城镇开发、长期订单里程碑、事件里程碑、永久荣誉与地标；
- 用于商店资格和未来扩城；
- 属于职业生涯型进度，当前不下降，避免因为一次灾害重新锁住已经开放的系统。

后期难度主要通过当地声望波动、物流上限、运营成本和跨城投入维持，而不是反复剥夺永久解锁。

## 7. 真实天气和灾害如何工作

两镇分别向现实城市取样，每 8 小时形成一个权威天气周期：

1. 服务端读取实时天气、逐日预报和当前预警；
2. 把供应商天气归一化为晴朗、降雨、高温、寒潮、强风或冰雹；
3. 把可信的现实预警映射为固定灾害规则；
4. 在服务器开始生产时固化产量和工期修正；
5. 前端只展示结果，不自行计算或提交倍率。

安全策略：

- 天气请求最多等待配置的超时时间；
- 同一城镇、同一 8 小时周期只执行一次在途请求；
- 当前天气与预警接口独立结算；预警接口失败时，可信的当前天气仍保持实时生效，但本窗口不会依据缺失预警新建灾害；
- 预警请求使用不超过 1 秒且不超过总预算一半的独立短超时；迟到的响应或拒绝会被安全接管，不会形成未处理 Promise；
- 观测时间超过 12 小时或比服务器时钟超前 1 小时以上的数据会被拒绝；
- 只有来源为实时数据或确定性规则、并且服务端显式标记 `mechanicsEnabled=true` 的快照才允许影响玩法；旧存档缺字段或来源异常时一律按关闭处理；
- 成功数据保留为最近可信快照；服务暂时异常时可展示不超过 72 小时的最近可信数据并明确标记，但该快照仅供展示，不再修改生产或触发新灾害；
- 没有可信数据时进入中性回退，天气机制关闭、灾害列表为空，不用伪造天气惩罚玩家。
- 现实预警使用供应商预警 ID 去重；同一响应出现重复 ID 时保留严重度最高、发布时间或生效时间更新的记录；同一预警跨越多个 8 小时窗口也只能激活一次，处理后不会再次发奖或重复生成灾害。

持久性灾害只由可信实时预警创建。本地规则仍会每天轮换普通世界事件，但安全回退、最近有效天气和未配置天气服务都不会随机生成减产、交通封锁或声望惩罚。

中性回退只中和天气缓存本身的倍率。此前由可信实时预警创建、尚未解决的既有灾害仍继续结算，直到玩家完成处置；前端会把这一区别明确告诉玩家。

当新的真实天气灾害开始时，上一轮三个产业的应急增产状态会全部清空，避免跨灾害继承一次性加成。青禾寒潮或供水类预警会映射为“河谷供水管冻裂”，实际降低农场产出、抬高当日采购成本，并提供抢修与永久改造选项；不是只有霜岭才有低温灾害。霜岭镇会把现实干旱映射为本镇的“高原干旱”内容，不会误用春融事件；天气机制 ID 和城镇表现内容 ID 分离，保证两镇共享规则结构但保持地方特色。

生产改善并不只来自“躲灾害”。玩家可通过轮作、营养计划、动物特质、地层勘探、设施升级、气象站、排水网、三业防护棚和灾期紧急行动主动提高产量或缩短工期。

## 8. LLM 世界导演

### 8.1 LLM 能看到什么

服务端为 LLM 生成裁剪后的庄园摘要，包括：

- 当前城镇及其特色；
- 三业等级、健康度、库存压力和加工队列；
- 当期天气、未来三日真实预报、现实预警和未处理灾害；
- 当天已选择的生产效果、两镇发展进度和联动项目实际缺口；
- 在途/待领取货物、当前产地可发货路线与装箱缺口；
- 今日物流余量；
- 当前目标、研究、NPC 结构化记忆；
- 本镇经营节奏、下一环节、是否因当日顺序而阻塞；
- 未来六个本地研究前沿及其点数、声望、前置和经营里程碑缺口；
- 三位本地顾问的信任等级、最近事实和当前三业指导效果；
- 永久荣誉分数、下一档奖励和本镇基础设施；
- 当日事件/灾害对三业买入价与售价的权威修正；
- 商店中已解锁、买得起且未达到限购的候选商品。
- 由服务器整理的、带稳定 ID 的事实依据候选，而不是让模型自行声称“依据了数据”。

不会把数据库、密钥、其他玩家私有数据或任意服务端对象交给模型。

### 8.2 LLM 可以做什么

- 从恢复、压力、机遇、共同体、发现、商路六种白名单中选择今日世界节拍；
- 用当前城镇、天气和最近行动生成有因果关系的世界叙事，并解释哪条产业链正在形成瓶颈；
- 从本地三位顾问中选择实际说话者，让台词与人物职责、信任和结构化记忆一致；
- 从服务器事实列表中选择 1—3 项依据，前端直接展示“本次导演依据”，避免建议看似聪明却无法核对；
- 生成不承诺必然发生的跨日伏笔，使事件处理后、研究完成后和跨城到货后有世界回声；
- 从服务器已有功能中选择三步行动焦点，给出今日经营建议和取舍理由；
- 在服务端给出的合法商品候选中推荐一项，或明确建议暂不购买；
- 为固定规则事件生成更贴合当前庄园的描述。

导演会在事件处理、订单/增值路线完成、研究解锁、设施建设、三项深度经营和顾问对话等关键变化后异步刷新。玩家操作期间若状态修订号已经变化，旧导演结果会直接作废，绝不会把基于旧库存的叙事合并到新状态；玩家处理完事件后则会正常生成一次“事后回声”，不再因为事件已有选项而错误判定任务过期。

这些能力提高世界连续性和“被世界回应”的感觉，但不会改变权威数值。模型返回的事件、节拍、顾问、证据、行动、商店和持续日数全部使用服务器候选索引；供应商返回真实 Token 用量时直接记账，仅在供应商不返回时使用估算值。

### 8.3 LLM 不能做什么

- 不能生成或修改金币、物品、声望、概率、价格、产量和工期；
- 不能决定操作是否合法；
- 不能绕过等级、库存、物流、限购或城镇限制；
- 不能凭空创建灾害；
- 不能把建议直接执行成玩家操作；
- 不能让商店出售服务端没有注册的商品；
- 输出超时、解析失败或越界时不能阻断庄园。

世界事件模板、灾害和所有效果仍由确定性的服务器规则决定。LLM 只选择白名单并生成有界表现层；调用失败、输出越界或完成期间状态改变时立即保留最新规则状态与规则建议。

## 9. 研究、深度经营、顾问、荣誉和基础设施

### 9.1 两棵独立研究树

青禾和霜岭各有 12 个研究项目，研究点、已解锁项目和前置关系分别保存，切换城镇不会共享进度。两棵树的结构角色相近，内容和数值不同：

| 分支 | 青禾示例 | 霜岭示例 | 实际作用 |
|---|---|---|---|
| 农业 | 土壤科学、系统轮作、精准灌溉 | 冻土保育、高寒轮作、地热滴灌 | 农场产量/工期、特色水利设施 |
| 牧业 | 动物营养、动物特质 | 牦牛营养、耐寒育种 | 牧场产量、特质与营养玩法 |
| 矿业 | 地层勘探、深层采矿 | 冰川地质、热脉采掘 | 矿山产量/工期、深层勘探 |
| 工程 | 庄园工程、三业自动化 | 寒区工程、低温自动化 | 三业工期、设施二/三级 |
| 社区 | 协作网络、合作社联运、庄园荣誉 | 山地互助、雪崩物流、极光荣誉 | 顾问记忆、高阶货运、传奇奖励 |

所有有生产描述的研究节点都直接修改权威三业规则；社区节点分别被顾问记忆、货运/设施门槛和传奇荣誉读取，不再存在“研究完成但其他板块完全不用”的纯文本项目。研究前置只允许引用本镇节点，并有自动无环审计。

研究不能再靠前期囤积点数直接毕业。每个节点同时校验本地研究点、当地声望、前置节点和至少一项真实经营里程碑，包括轮作/牧群/勘探次数、矿山防护、加工与设施建设、顾问交流、订单与增值路线、特色设施等级、永久荣誉和完整本地循环。青禾全树研究点成本提高到至少 250，霜岭整体更高；根节点也必须先完成一次对应产业实践。特色设施一级不依赖其后置研究，因此不存在“研究要求先建设、建设又要求先研究”的循环锁。

### 9.2 深度经营不是文字卡

农场轮作计划会改变土壤健康、后续农场产出与轮作图鉴；牧群计划会改变健康、特质和牧场产出；矿层调查会改变防护、矿石奖励和矿山产出。每个板块每天只能完成一次对应计划，必须消耗本地资源或满足保护等级。相关百分比与研究、事件、灾害、顾问和设施统一汇总后传给三业引擎。

### 9.3 本地顾问和结构化记忆

青禾顾问为林禾、苏岚、乔岩；霜岭顾问为洛桑次仁、德吉央金、索朗多吉。三位顾问分别负责农、牧、矿，不跨镇复用姓名和人物设定。

每天与顾问深入交流会提高亲和与信任，并立即生成当日权威指导：根据主题为对应产业提供 `产出 +2%～7%` 或 `工期 -2%～7%`。未完成社区研究时每人只保留最近 2 条结构化事实，完成后最多保留 8 条；LLM 只能读取这些有界事实生成连续对话，不能自行添加数值效果。

### 9.4 永久荣誉和 128 项图鉴

旧赛季重置已替换为不清零的职业生涯荣誉。每座当前可玩城镇均生成 128 项图鉴，覆盖设施等级、加工层级、作物/轮作、动物/特质、矿层、研究、顾问信任、深度经营、货运和荣誉本身。

图鉴按难度奖励 1、3、8、20、50 分，对应普通、进阶、稀有、史诗、传奇。永久奖励线为 25、80、180、350、600 分；最高档还要求完成本镇荣誉研究。青禾在排除最高档荣誉自身后仍有 627 个可达分值，霜岭为 644，因而不会出现“必须先拿传奇图鉴才能到传奇分”的循环锁。

### 9.5 通用与特色基础设施

每镇都有三项同结构基础设施：三业调度中心、综合仓配站、生产保障中心；它们使玩家容易理解共同规则。每镇另有两项特色设施，体现真正差异：青禾是河谷水利实验站和合作社冷链中心，霜岭是地热温室群和雪崩防控与热力调度站。

设施共三级，消耗金币、当地研究点和本地合金；二级以上要求对应本地研究。其产量、工期和售价效果直接进入三业与市场，高级货运/联动项目也读取设施等级。

旧版霜岭“简化本地三产业槽”不再作为主页面的第四套重复玩法；旧字段和动作只为存档与旧客户端兼容。新的本地产业协作由完整农牧矿、深度经营、特色设施、加工路线和跨城合同承担。后续 DLC 也遵循这一原则，不再为每城复制一套低信息量的三槽小游戏。

## 10. 每日轮换商会

商会目录现有 21 项：3 项跨镇通用品、9 项青禾物资包、9 项霜岭物资包。每天每镇只展示 3 项，其中 1 项通用、2 项本地；组合按账户、城镇和北京时间日期确定性刷新，服务端和重连后的客户端始终一致。

| 类别 | 示例 | 规则 |
|---|---|---|
| 通用便利 | 优先调度券、商会联运票 | 不产生资源，只缩短一次任务或折扣一次客运 |
| 收藏回收 | 商会纪念旗 | 纯展示、高价金币出口 |
| 青禾物资 | 面粉、饲料、土壤箱、工作服、铁锭、矿务箱等 | 只能在青禾当日候选中出现 |
| 霜岭物资 | 霜麦粉、高原饲料、营养基、呢毡、耐寒合金等 | 只能在霜岭当日候选中出现 |

每项同时有持有上限和每日购买上限，当前均至少为每日 1 次；跨日会重置购买台账并生成新候选。购买资源包后物资立即进入当前城镇对应的农场、牧场、矿山或加工库存。LLM 只从当天三项合法候选中解释推荐理由，不能添加商品或绕过资格、余额和限购。

## 11. 前端和规则一致性

前端按“城镇导航—今日决策—三业经营—长期成长”组织信息，并遵循以下约束：

- 农场、牧场和矿山页面只读取当前城镇返回的目录；
- 霜岭页面不会索引青禾作物、动物或矿脉；
- 所有库存访问对旧存档缺失项使用安全零值；
- 所有操作都携带当前城镇和对应修订号；
- 前端防旧快照判断以城镇 ID 为命名空间：同一城镇拒绝修订号回退，切换到另一城镇时允许目标镇从较低修订号开始，并清空原城镇的选择、邻居和操作草稿；
- 服务端 409 冲突会触发刷新，避免重复收取或旧页面误操作；
- 同一玩家的跨页面写入由账户锁串行化，多实例部署也不会因为两个服务进程同时结算而覆盖金币、声望或城镇状态；
- 金币、物流、原料、前置研究和灾害封锁都显示为明确禁用原因；
- 天气来源、更新时间、过期状态和是否影响玩法均可见；
- 未开发的潮汐港与赤岩城只显示规划预览，不提供无效按钮；
- 桌面、平板和手机布局使用同一功能集合。

前端已按页面动态加载大厅、房间、聊天、农场、牧场、矿山、庄园和后台管理。庄园功能脚本约 55 kB（gzip 约 18 kB），后台管理的较重组件不会进入普通玩家首屏；组件依赖不再被强制合并为单个 853 kB 文件。生产构建保留 525 kB 的最大共享分块告警预算，防止后续内容无声膨胀。

庄园大页面收到新快照时使用低优先级提交，但点击后的忙碌态和按钮禁用同步生效；整页倒计时从每秒重绘调整为每 5 秒，后台静默刷新为 30 秒。这样减少大 DOM 重算，同时不牺牲服务端计时精度。

## 12. 后续城镇扩展方向

本轮不开发新的 DLC 城镇，后续按以下顺序扩展：

1. 潮汐港：规划使用青岛作为天气锚点，未来围绕潮汐窗口、水产养殖、盐矿、冷链和保鲜；
2. 赤岩城：规划使用新疆哈密作为天气锚点，未来围绕缺水农业、驮畜、铜盐矿和能源调度。

两镇当前都只保留只读规划卡片，不注册到可玩城镇、交通、生产或天气轮询中。

新城镇接入必须完成以下清单：

1. 注册城镇元数据、现实天气锚点、解锁条件和交通路线；
2. 提供完整作物、动物、产品和矿产目录；
3. 提供二级、三级加工品和正运营成本配方；
4. 用增值项目覆盖全部初级产品；
5. 提供独立订单、事件、灾害和修复选项；
6. 为通用研究和设施角色提供本镇替代物；
7. 通过跨城镇污染、零金币恢复、存档迁移、前端可达性和经济闭环测试；
8. 在真实运营数据证明前，不增加新的永久倍率系统。

## 13. 运行配置

真实天气为可选服务端能力：

```dotenv
QWEATHER_API_HOST=https://你的专属API-HOST.qweatherapi.com
QWEATHER_API_KEY=你的服务端密钥
QWEATHER_TIMEOUT_MS=3000
QWEATHER_FORECAST_DAYS=3
```

环境变量只作为首次启动引导。管理员可以在账号管理页启停天气、填写专属 API Host/API Key、设置超时与 1—10 天预报范围，并修改青禾/霜岭的城市名和经纬度；保存后立即生效。“测试连接”必须同时取得两镇实况和至少一天有效逐日预报才算成功。持久化 API Key 使用会话密钥派生的 AES-256-GCM 密钥加密，管理接口只返回“已配置”状态，不回传明文。未配置时庄园仍可完整运行，但会明确显示中性天气回退，现实天气不会影响生产。

服务端使用 `X-QW-Api-Key` 请求头，不把密钥拼入 URL；实时天气使用 `/v7/weather/now`，每日预报使用当前 `/weather/v1/daily/{latitude}/{longitude}` 路径和必需经纬度，并传入 1—10 的 `days` 参数。和风天气当前仍支持 API Key，但官方已推荐 JWT；若 2027 年后请求量接近 API Key 限额，应再把账号页升级为 Ed25519/JWT 凭据配置。

默认现实城市映射为：青禾镇—郑州、霜岭镇—拉萨、潮汐港规划—青岛、赤岩城规划—新疆哈密。后两镇目前只保存规划元数据，不发起天气请求。

当前天气、逐日预报和预警接口分别遵循和风天气官方文档：

- <https://dev.qweather.com/docs/api/weather/weather-now/>
- <https://dev.qweather.com/docs/api/weather/weather-daily-forecast/>
- <https://dev.qweather.com/docs/api/warning/weather-alert/>

## 14. 完整规则审查结论

当前静态规则和自动化审计未发现不可恢复死锁：

- 两镇研究各 12 项、节点不共享、前置无环，所有生产研究均进入真实三业倍率；
- 24 个研究节点全部具备真实经营门槛，单有 999 点研究和声望仍不能跳过产业实践；两镇全树研究点成本均不低于 250；
- 青禾与霜岭具有相反的三业操作顺序，完成阶段会直接改变权威产量、工期或售价，完整循环也进入研究门槛；
- 每镇 128 项图鉴，扣除最高档本身后仍可达到 600 分传奇线；
- 6 条货运均有唯一产地、目的地、可达研究/设施前置和真实消费项目；
- 当地声望不会低于 0，已永久解锁城镇不会因声望下降重新上锁；
- 每日物流、商店限购、加工日限次和货运成本共同阻止无限同日套利；
- 母鸡购买价为 180，金矿单份售价为 260；动物转卖价约为购入价一半，不能通过买卖动物刷钱；
- 6 条跨城项目奖励均高于材料与运费机会成本，但收益率不超过 1.4 倍，提供选择价值而不成为唯一答案；
- 事件、灾害与设施的买入/售价修正由服务端计算，农、牧、矿卡片展示价与最终扣款/收入使用同一规则；
- 青禾供水管冻裂会真实影响农场与采购价，顾问指导、深度经营和基础设施也都能追溯到三业结果；
- 旧存档缺少研究分镇、商店台账、小数余数、荣誉、设施或本地经营节奏字段时会迁移为安全默认值。

游戏性结构已经形成“今日事件取舍—三业生产—深度经营—设施建设—跨城物流—图鉴荣誉”的多层循环。经济系统具有投入、周转、风险、便利和收藏五类金币出口；成长系统同时保留产业等级、当地声望、本地研究、顾问信任、设施、跨城和永久荣誉，不再只靠三业升级。

仍不能仅靠静态测试证明长期平衡。最需要实际运营数据确认的是：新玩家第几天首次缺钱、各研究解锁中位天数、600 分荣誉完成时长、三业收益占比、灾害应对率、商店购买率、跨城项目选择率和 LLM 建议采纳率。若任一收益路线长期占比超过约 35%，应优先调整原料机会成本、物流消耗或日限次，而不是全局涨价。

## 15. 后续建议与运营指标

规则闭环已经建立，但长期平衡仍应通过真实玩家数据持续校准：

- 第 7、30、60、90 天的留存目标剩余量；
- 三业活跃操作占比；
- 初级产品直售与加工消耗比例；
- 每条加工配方、订单和增值路线的使用率；
- 每日物流的平均使用量和选择分布；
- 灾害平均处理时间与当地声望净变化；
- 每周交通次数和交通费占收入比例；
- 商店购买率、加速券使用率和纪念品持有量；
- LLM 回退率、延迟、推荐采纳率和单活跃用户成本；
- LLM 证据引用率、顾问匹配率、伏笔次日承接率、关键操作后的导演刷新成功率与旧状态结果作废率；
- 两镇金币净流入、净流出以及玩家破产后的恢复时间。

下一轮建议按以下顺序推进：

1. 先接入 14、30、60 天经济模拟和线上遥测，校准荣誉阈值、研究成本与跨城收益；
2. 基于已经落地的事实引用和跨日伏笔，继续做 3—7 日有界剧情弧：只保存服务器审核后的主题状态与未兑现线索，不保存自由文本规则，也不允许模型直接改数值；
3. 为研究、基础设施和图鉴增加筛选、分支概览与下一目标推荐，避免 128 项内容带来信息拥挤；
4. 对低端移动设备测量庄园长列表的交互延迟，若仍超过 100 ms，再对图鉴和研究列表做可视区域渲染；
5. 等青禾—霜岭数据证明跨城循环成立后，再开发潮汐港；赤岩城继续保持规划状态。

如果某条路线成为唯一最优解，应优先调整机会成本、原料组合或日限次，而不是简单把全体价格一起上调。
