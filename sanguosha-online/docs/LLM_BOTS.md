# 大模型机器人架构

当前仅斗地主接入可选大模型决策。三国杀和够级继续使用原有同步规则机器人，但三种游戏共用 `BotDecisionRegistry` 扩展边界，后续可以分别注册自己的私有视图适配器。

## 安全边界

1. 规则引擎先生成合法候选动作。
2. 游戏适配器只投影机器人自己的手牌与公开信息，不传房间号、玩家 ID、昵称或其他玩家手牌。
3. 模型只能返回候选序号，不能自行构造动作。
4. 返回序号由注册表复验，最终动作仍交给权威规则引擎校验。
5. 超时、网络错误、无效 JSON、越界序号或预算耗尽时，立即使用本地规则策略。

API Key 仅由服务端环境变量读取，不会进入房间快照、浏览器响应或日志。

## Token 控制

大模型模式是混合模式，不会每一步都调用模型：

- 强制动作和低价值动作直接采用本地策略。
- 输入使用短字段、牌面点数、公开手牌数量和候选序号，不发送日志或自然语言牌局复述。
- 候选动作按等级最多保留 3、4、5、6、7、8、10 个。
- 每局最多调用 1、2、3、4、6、8、10 次，对应智力等级 1—7。
- 默认每局累计输入上限为 3,500 Token。
- 单次输出默认最多 16 Token，只允许 `{"i":序号}`。
- 服务重启后调用数和 Token 用量从房间快照恢复；下一局重新计数。

供应商未返回 `usage` 时，服务端按字符数保守估算 Token。

## 智力等级

| 等级 | 称号 | 本地策略特征 | 大模型使用 |
|---|---|---|---|
| 1 | 新手牌友 | 会在前几个合法动作中随机选择 | 仅极少量残局决策 |
| 2 | 稳健农民 | 以较小合法牌为主，偶尔选择次优动作 | 最多 2 次 |
| 3 | 欢乐牌手 | 优先组合牌与低成本压制 | 叫分与短残局 |
| 4 | 记牌能手 | 更重视保留炸弹和公开手牌数量 | 关键分歧局面 |
| 5 | 叫分专家 | 加入农民同伴协作和叫分判断 | 最多 6 次 |
| 6 | 残局大师 | 优先阻止即将走完的对手 | 最多 8 次 |
| 7 | 牌桌宗师 | 评估出牌后的剩余牌组结构 | 最多 10 次 |

无论选择哪个等级，模型都看不到其他玩家未公开手牌。

## 服务端配置

服务端支持 OpenAI-compatible Chat Completions JSON 接口。三个主要参数必须同时配置；全部留空时禁用大模型供应商：

```dotenv
DOUDIZHU_LLM_ENDPOINT=https://供应商地址/v1/chat/completions
DOUDIZHU_LLM_API_KEY=替换为服务端密钥
DOUDIZHU_LLM_MODEL=替换为低成本模型名
DOUDIZHU_LLM_TIMEOUT_MS=4000
DOUDIZHU_LLM_MAX_OUTPUT_TOKENS=16
DOUDIZHU_LLM_MAX_PROMPT_TOKENS_PER_GAME=3500
```

创建斗地主房间时可选择“规则机器人”或“大模型优先”。如果房间选择了大模型、但服务端没有配置供应商，房间会明确显示“规则回退”，牌局仍可正常进行且不消耗 Token。
