# 墨鱼

面向电脑浏览器的私人游戏与功能工作区。游戏区当前支持三国杀、山东够级、经典斗地主、璀璨宝石、璀璨宝石宝可梦和数字炸弹，并采用服务端权威模型；功能区提供本地 TXT 小说阅读。浏览器只展示当前账号可见的游戏信息，小说文件默认仅保存在当前浏览器。

## 项目功能

- 管理员创建、停用玩家账号和重置密码，不开放公开注册。
- 管理员可在 Web 后台启停三国杀与斗地主大模型机器人、配置 DeepSeek API Key 和模型；默认使用 DeepSeek V4 Flash，也可输入其他可用模型 ID。
- 创建房间时可选择六款游戏，共用账号、房间、实时网络、断线重连和持久化。
- 真人开房、加入、准备、选将/出牌和实时多人对局。
- 六种游戏都支持房主添加服务器机器人补位；机器人只读取自己的私有游戏视图。
- 原版默认 160 张牌、66 名武将、124 个技能规则。
- 标准、SP、风、火、林、山、神武将包与神将势力选择。
- 服务端持久化房间和对局，支持服务重启恢复及断线重连。
- 浏览器端隐藏他人手牌和未公开身份，服务端复验每个操作。

### TXT 小说阅读

- 支持 UTF-8、UTF-16、GBK/GB18030 中文 TXT，并可手动指定编码。
- 自动识别“第 X 章/回/卷/节”，无章节标题时按长度生成阅读分节。
- 使用浏览器 IndexedDB 保存最近导入的书、章节与滚动进度，不自动上传服务器。
- 支持字号、行距、白纸、护眼和夜间主题。
- 点击“文档模式”或按 `F9` 后切换为技术手册/PDF 风格；小说正文、滚动、翻章与进度保存继续工作，再次按 `F9` 恢复普通阅读界面。

### 够级

- 固定 6 人、3V3，甲乙联邦交错落座，对家相隔三席。
- 196 张牌；开局由服务器自动完成缺 3、缺 4 的买牌结算。
- 支持同点数组牌与挂 2/王、憋 3、4 一次打完、够级隔离、开点、烧牌和让牌。
- 出完牌依次结算头科、二科、三科、四科、二拉和大拉，并按联邦名次判胜。
- 机器人采用“合法优先、最小压制”策略，所有选择仍经过与真人相同的权威规则校验。

### 斗地主

- 固定 3 人、标准 54 张牌；依次叫分，最高叫分者成为地主并获得 3 张底牌。
- 支持单张、对子、三张、三带、顺子、连对、飞机、四带二、炸弹和王炸。
- 两家连续不出后由上一手玩家重新领牌；炸弹、王炸和春天参与倍率结算。
- 服务端隐藏其他玩家手牌并校验叫分、牌型与压牌关系；机器人使用随机网名，并在每次操作前随机等待 1–5 秒。
- 斗地主房间可选“规则机器人”或“大模型全程决策”；大模型每次行动都从规则引擎生成的合法候选中选择，不可用、超时或返回无效结果时自动回退。
- 机器人智力分为 1—7 级；选择大模型后每次机器人行动都会调用，等级差异由分级提示词实现。斗地主上下文包含紧凑公开出牌摘要、剩余手牌规划和合法候选结果，不携带冗长聊天历史；真人也可自动获取大模型出牌推荐。完整设计见 [大模型机器人架构](./docs/LLM_BOTS.md)。
- 进入房间的首局三名玩家各获得 10,000 欢乐豆；后续牌局沿用上一局余额。单份输赢为“底分 × 当前倍率 × 100”，地主承担两份、每名农民承担一份，结算不会把余额扣成负数。
- 牌局结束后展示欢乐豆账目，并由真人选择离开或继续下一局；机器人自动同意，所有真人确认后重新发牌。
- 房间、叫分、牌局和私有视图均可随服务重启恢复。

### 璀璨宝石

- 支持 2—4 人经典规则：收集宝石、购买三级发展卡、保留卡牌、获得黄金以及吸引贵族。
- 达到 15 声望后完成等回合终局；同分时持有发展卡更少者优先。
- 公开保留牌对所有玩家可见，暗抽保留牌只向持有者展示；服务器始终保存完整牌堆与随机状态。

### 璀璨宝石宝可梦

- 支持 2—4 名训练家，使用 Lv.1—3、稀有与传说共 90 张宝可梦卡牌和六类精灵球。
- 可从场上或保留区免费完成宝可梦进化；稀有和传说卡要求实际支付大师球。
- 达到 18 分后完成等回合终局；同分时进化次数更多者优先。

### 数字炸弹

- 固定双人对战，建房时可选择 1—8 位密码，默认 4 位；允许重复数字和前导零。
- 双方秘密出题并轮流猜测，出题者只手动反馈“位置完全正确”的数量，系统不代替玩家核验答案。
- 5 次内猜中获得 10 分，之后逐次递减，最低 1 分；每局后双方共同决定继续下一局或最终结算，累计分数保留。

### 三国杀

- 三国杀房间可选“规则机器人”或“大模型全程决策”；选择大模型后，每次轮到机器人操作都会调用当前模型。
- 大模型只接收机器人自己的手牌、公开局面与合法候选编号，智力等级由分级提示词控制；调用失败、超时或返回无效结果时自动执行规则回退。

本项目按用户要求让所有房间成员随机身份，因此房主不再固定为主公；这与原 Java 固定玩家 1 为主公的流程不同。完整核查见 [原版规则差异核查](./docs/RULE_AUDIT.md)。

## 技术架构

- `web`：React、Vite、Ant Design、Socket.IO Client
- `server`：Node.js、Express、Socket.IO、PostgreSQL
- `shared`：无 IO 的服务端权威规则核心
- `deploy`：Docker Compose 与 Nginx 示例配置

前端主导航按“游戏”“功能”“管理”分区。六款游戏各有独立规则状态与牌桌界面，不在浏览器端共享或混合权威状态。

要求 Node.js 22、pnpm 11；生产部署要求 Docker、Docker Compose，使用反向代理时建议配合 Nginx 和 HTTPS。

## 本地开发

1. 启动 PostgreSQL，并创建可用数据库。
2. 复制环境变量模板：

   ```bash
   cp .env.example .env
   ```

3. 修改 `.env` 中的 `DATABASE_URL`、`SESSION_SECRET` 和初始管理员密码。
   三国杀与斗地主大模型机器人推荐在管理员 Web 后台配置；环境变量仅作为可选的首次启动引导配置，留空时默认禁用。
4. 安装依赖并启动：

   ```bash
   corepack enable
   pnpm install --frozen-lockfile
   pnpm dev
   ```

默认开发端口为 Web `5173`、Server `3000`。`APP_ORIGIN` 应与浏览器访问来源一致。

### 无数据库的本地测试模式

如果本机没有 Docker 或 PostgreSQL，可先构建前后端，再启动只监听本机的临时测试站点：

```bash
pnpm --filter @sanguosha/shared build
pnpm --filter @sanguosha/web build
pnpm --filter @sanguosha/server build
pnpm --filter @sanguosha/server start:local
```

访问 `http://localhost:3000`，默认账号为 `admin`，密码为 `moyu-local-2026`。该模式仅供本机功能测试，账号、房间和对局保存在内存中，服务关闭后会清空；正式部署仍必须使用 PostgreSQL。

## Docker 生产部署

1. 在服务器安装 Docker Engine 与 Docker Compose Plugin。
2. 将项目上传到服务器，例如 `/opt/sanguosha-online`。
3. 在项目根目录创建 `.env`，至少填写：

   ```dotenv
   POSTGRES_PASSWORD=使用仅含字母数字下划线或短横线的随机密码
   SESSION_SECRET=至少32位随机字符串
   INITIAL_ADMIN_USERNAME=admin
   INITIAL_ADMIN_PASSWORD=首次登录密码至少8位
   INITIAL_ADMIN_DISPLAY_NAME=管理员
   APP_ORIGIN=https://你的域名
   APP_VERSION=1.0.0
   BUILD_SHA=可选的7至64位Git提交摘要
   ```

   不要提交 `.env`。生产环境的 `APP_ORIGIN` 必须使用 HTTPS。

4. 构建并启动：

   ```bash
   docker compose up -d --build
   docker compose ps
   ```

5. 应用只绑定宿主机 `127.0.0.1:3100`。将 `deploy/nginx-moyu.conf` 复制为站点配置，修改 `server_name`，保留 `/socket.io/` 的 WebSocket Upgrade 头，再配置 TLS。
6. 验证部署：

   ```bash
   curl -fsS https://你的域名/healthz
   curl -fsS https://你的域名/version
   ```

数据库保存在 Docker volume `sanguosha_db`。升级前应先备份该 volume；不要使用 `docker compose down -v`，否则会删除数据库。

## 发布内容

GitHub 源码应包含本目录内的源文件、测试、Docker 配置、部署示例和文档；不要上传 `node_modules`、`dist`、`.env`、日志或本地压缩包。Release 使用项目生成的部署压缩包，解压后按上面的 Docker 步骤部署。

## 验证

```bash
pnpm check
```

该命令依次执行类型检查、测试和构建。规则迁移历史见 [迁移矩阵](./docs/RULES_MIGRATION.md)，产品边界见 [产品说明](./docs/PRODUCT_SPEC.md)。
